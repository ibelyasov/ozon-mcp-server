## Actual headless Chromium lifecycle

The one explicitly ignored Rust test, `runtime::browser::tests::real_chromium_headless_lifecycle`, was run separately against installed Chrome and fresh disposable profiles. It navigates and evaluates a local data page, verifies cancellation and confirmed exit before replacement, verifies aborted-task cleanup, and recovers an exactly recorded surviving browser through CDP before a fresh launch.

The final monitored run passed in **2.485 s**. Native macOS `NSWorkspace` and `CGWindow` sampling recorded **92 samples** over four owned Chromium launches: foreground remained unchanged; no owned Chromium process appeared as foreground or owned an onscreen window. Artifacts: `.work/full-review/runtime/final-headless/{measure-focus.py,real-chromium.log,real-chromium-focus.json,browser-version.json}`.

This proves the tested default headless lifecycle on this machine. It does not test Ozon, user sign-in, visible manual setup, or Linux browser execution. The profile must be exclusive to this broker. Existing native Singleton markers cause pre-spawn refusal and are preserved. An unrelated Chrome launched concurrently between inspection and spawn remains outside the atomic guarantees of this guard; see [runtime ownership](../behavior.md#ownership-cancellation-and-recovery).

## Actual MCP stdio and shared broker

The final debug executable was exercised through two real stdio frontends and one explicitly owned broker, with no configured browser executable and no network access. The acceptance script created a new private temporary journal and inserted a fixture only into that new database.

The final run passed in **0.319 s**:

- Both clients initialize and discover exactly the canonical eight tools and schemas.
- Concurrent local calls use the shared broker and accept schema-valid integral JSON decimals.
- Notes are idempotent across clients and retrievable by exact selection.
- Retired arguments are rejected; a marketplace call without the explicit executable returns the canonical configuration failure before browser launch.
- Graceful shutdown removes the owned socket and leaves the versioned journal and one durable note.

Artifacts: `.work/full-review/stdio-final/{acceptance.py,results.json,broker.log,frontend-0.log,frontend-1.log}`. The first run remains in `.work/full-review/stdio/`: its script expected a nonexistent `INVALID_CONFIGURATION` public code. The approved schema and actual server correctly use `INVALID_ARGUMENT`; the corrected assertion also checks the executable-setting message. No production change was needed.
